# ADR-005: 任务取消的安全边界

- **状态**：Accepted
- **日期**：2026-07-31
- **决策者**：SteadyChunks 项目

## 上下文

高速跑图中，玩家频繁改变方向会导致大量已派发的区块生成任务变成"过期需求"。如果这些任务继续推进，会：

1. 占用工作线程与资源令牌，挤压玩家前方任务；
2. 生成不会被玩家看到的区块，浪费 CPU 与内存；
3. 在 FULL 整合与发送队列形成积压；
4. 增加 ProtoChunk 峰值驻留数量。

但 Minecraft 世界生成的多个阶段涉及共享状态、邻块依赖、结构引用、文件写入等，盲目中断会产生：

- 部分结构（Piece 截断、引用丢失）
- 部分光照（边界接缝、黑块）
- 部分后处理（方块状态不一致）
- 依赖环（被取消任务仍被其他区块依赖）
- 存档损坏（写入中断）

## 决策

SteadyChunks 采用**软取消**策略，仅允许在任务边界取消，禁止中断运行阶段。

### 5.1 允许的取消操作

- 从等待队列移除尚未开始的任务
- 阻止尚未开始的阶段进入执行
- 阻止任务进入下一个高成本阶段（如从 BIOMES 完成后阻止进入 NOISE）
- 释放未使用的资源令牌
- 标记任务为 `CANCELLED`，让上游依赖感知

### 5.2 禁止的取消操作

- 中断正在写区块的阶段（NOISE / SURFACE / CARVERS / FEATURES）
- 中断 FEATURES 中的结构或特征放置
- 中断光照传播
- 中断保存（IO 写入）
- 取消仍被其他区块依赖的共享任务（如 STRUCTURE_REFERENCES 跨区块引用）

### 5.3 依赖引用计数

- 每个任务维护 `dependents` 计数（其他区块依赖本任务的完成）；
- 软取消前检查 `dependents`：
  - `dependents == 0` 且任务尚未开始：可取消
  - `dependents > 0`：不可取消，但可降级优先级
- 依赖解锁任务拥有保底优先级和保留 permit（计划 §3 风险缓解）

### 5.4 取消时机

按安全等级分级：

| 阶段 | 安全等级 | 取消策略 |
|---|---|---|
| `EMPTY` → `STRUCTURE_STARTS` 等待 | A | 可取消 |
| `STRUCTURE_STARTS` 执行中 | C | 不可中断；完成后可阻止下一阶段 |
| `STRUCTURE_REFERENCES` 等待 | A | 可取消（若依赖计数为 0） |
| `BIOMES` 等待 | A | 可取消 |
| `BIOMES` 执行中 | A | 不可中断；完成后可阻止下一阶段 |
| `NOISE` 执行中 | B | 不可中断 |
| `SURFACE` 执行中 | B | 不可中断 |
| `CARVERS` 执行中 | B | 不可中断 |
| `FEATURES` 执行中 | C | 不可中断（结构放置不可中断） |
| `LIGHT` 执行中 | B | 不可中断（光照传播不可中断） |
| `SPAWN` 等待 | A | 可取消 |
| `FULL` 整合 | D | 必须在主线程执行；可推迟，不可取消 |
| 区块发送 | A | 可推迟，可丢弃（若玩家不再需要） |

### 5.5 过期需求处理

- 玩家改变方向后，标记远离方向的任务为 `STALE`；
- `STALE` 任务保留执行权（不中断），但优先级降低；
- `STALE` 任务完成后不进入发送队列，直接释放；
- 队列年龄超过阈值的 `STALE` 任务可软取消（若依赖允许）。

### 5.6 故障注入验证

按计划 §11.2，测试以下场景下 permit 与缓存清理：

- 工作线程抛出异常
- 维度在任务等待时卸载
- 玩家退出
- 服务器停止
- Chunk Ticket 消失
- 保存失败
- 数据包重载
- 客户端断开
- 光照任务异常
- 模组结构生成异常

## 后果

### 正面

- 不产生部分结构、部分光照、部分后处理；
- 依赖关系不会因取消而断裂；
- permit 在正常、异常、取消路径均能释放，无泄漏；
- 与 ADR-004 严格正确性政策对齐。

### 负面

- 过期任务仍会占用 CPU 至当前阶段完成，无法立即释放；
- 软取消的效果依赖任务粒度，长 FEATURES 阶段的过期任务仍会拖累；
- 依赖引用计数需要严格验证，否则可能死锁或泄漏；
- 玩家快速来回切换方向时，取消与重新派发可能形成抖动。

## 备选方案

### A. 硬中断（Thread.interrupt）

被否决：
- Minecraft 世界生成代码不检查中断标志；
- 中断会导致方块状态不一致、结构截断、光照接缝；
- 文件写入中断可能损坏存档；
- 违反 ADR-004 严格正确性政策。

### B. 不取消，让过期任务自然完成

被否决：
- 高速跑图时过期任务会堆积，挤压前方任务；
- ProtoChunk 峰值驻留数量无法控制；
- 无法实现"完成优先"调度策略。

### C. 跨 Tick 保存函数栈，下次 Tick 继续

被否决：
- Java 不支持原生 continuation，需手动改写所有生成函数为状态机；
- 工程量巨大，且极易引入正确性 bug；
- 改变原版生成语义，违反 ADR-004；
- 计划 §3 明确列为非目标。
