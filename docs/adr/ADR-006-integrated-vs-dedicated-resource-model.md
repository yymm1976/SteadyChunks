# ADR-006: 集成服务器与独立服务器的资源模型

- **状态**：Accepted
- **日期**：2026-07-31
- **决策者**：SteadyChunks 项目

## 上下文

SteadyChunks 同时支持两种部署模型：

1. **单人集成服务器**（Integrated Server）：客户端与服务端同进程，共享 CPU、内存、GC、I/O；
2. **独立服务器**（Dedicated Server）：纯服务端进程，无客户端渲染负载。

两种模型的资源争抢模式完全不同：

| 维度 | 集成服务器 | 独立服务器 |
|---|---|---|
| CPU 竞争者 | 渲染线程、客户端主线程、音频、输入、GC、Section 编译线程 | 仅服务端主线程、网络线程、GC、I/O |
| 关键保护对象 | Render Thread、Client Main Thread、Section 编译队列 | Server Thread、网络线程、I/O |
| 玩家数量 | 1 | 多 |
| 视距影响 | 直接影响客户端编译负载 | 仅影响区块发送量 |
| 反馈来源 | 客户端本地帧时间、Section 编译队列 | 网络 RTT、客户端可选反馈 |
| 失败模式 | 渲染线程饥饿 → 帧时间尖峰 | 网络发送洪峰 → 客户端卡顿 |

单一资源策略无法同时满足两种模型：

- 集成服务器下，工作线程占满 CPU 会让渲染线程饥饿，直接导致帧时间尖峰；
- 独立服务器下，渲染保护逻辑无意义，反而会浪费可用的 CPU 核心；
- 独立服务器多玩家场景需要公平性，集成服务器单玩家不需要。

## 决策

SteadyChunks 区分两种运行模式，采用**不同的默认资源策略**。

### 6.1 模式检测

- 启动时通过 `FMLEnvironment.dist` 判断：
  - `Dist.CLIENT` 且 `ServerProperties` 指示为 integrated：集成服务器模式
  - `Dist.DEDICATED_SERVER`：独立服务器模式
- 模式可在配置中覆盖（`[governor] mode = "auto" | "integrated" | "dedicated"`）。

### 6.2 集成服务器默认策略

优先保护：

1. Render Thread
2. Client Main Thread
3. Server Thread
4. 音频与输入响应
5. GC
6. 区块网格编译线程（SectionRenderDispatcher）

资源策略：

- `reserve_logical_processors = 2`（保留 2 个逻辑处理器给客户端）
- `worker_threads_max = min(4, available - 2)`
- `max_inflight_total = 64`（控制 ProtoChunk 驻留）
- FEATURES 并发较低（默认 1，最大 2）
- 严格 FULL 与发送平滑
- 监听客户端帧时间反馈，触发紧急模式

### 6.3 独立服务器默认策略

优先保护：

1. Server Thread
2. 网络线程
3. GC
4. I/O
5. 其他玩家的活动区块

资源策略：

- `reserve_logical_processors = 1`（保留 1 个逻辑处理器给主线程与网络）
- `worker_threads_max = min(available - 1, 8)`
- `max_inflight_total = 128`（更高吞吐量）
- FEATURES 并发较高（默认 2，最大 3）
- 平滑的 FULL 与发送配额，但允许更高吞吐
- 多玩家公平性调度
- 不依赖客户端反馈，可关闭

### 6.4 预设

按计划 §11.6 提供三套预设：

| 预设 | 适用 | FEATURES 并发 | FULL 平滑 | 发送配额 | 客户端反馈 |
|---|---|---|---|---|---|
| `smooth_integrated` | 单人冒险整合包 | 低 | 严格 | 严格 | 启用 |
| `balanced` | 普通服务器 | 中 | 中 | 中 | 可选 |
| `throughput_server` | 独立服务器 / 预生成 | 高 | 宽松 | 宽松 | 关闭 |

### 6.5 自适应控制器输入差异

按计划 §4.2，控制器采用滑动窗口输入：

- 集成服务器：使用 P95/P99 帧时间、客户端编译队列作为关键信号
- 独立服务器：使用 P95/P99 MSPT、网络发送队列作为关键信号
- 两者共用：CPU、堆压力、GC 暂停、FULL 等待队列

### 6.6 紧急模式触发差异

集成服务器紧急模式额外触发：
- 连续长帧
- 客户端编译队列暴涨

独立服务器紧急模式额外触发：
- MSPT 超过硬上限
- 区块发送队列暴涨

## 后果

### 正面

- 两种模型都有合理默认，无需用户手工调参；
- 集成服务器下渲染保护逻辑生效，避免帧时间尖峰；
- 独立服务器下充分利用 CPU，吞吐量更高；
- 预设简化用户选择。

### 负面

- 必须维护两套默认值与测试矩阵；
- 集成服务器的客户端反馈依赖同进程时钟，独立服务器需退化为本机指标；
- 配置项数量增加，文档需清晰说明预设覆盖范围。

## 备选方案

### A. 单一资源策略（不区分模式）

被否决：
- 集成服务器下若按独立服务器策略（高并发），渲染线程饥饿，帧时间尖峰；
- 独立服务器下若按集成服务器策略（低并发），CPU 利用率不足，吞吐量低；
- 二者核心目标矛盾，单一策略必然顾此失彼。

### B. 自动检测模式但不提供预设

被否决：
- 用户难以理解默认值背后的逻辑；
- 升级时默认值变化难以追踪；
- 预设提供"配置快照"，便于复现与对照基准。

### C. 仅支持集成服务器，独立服务器留给后续版本

被否决：
- 计划 §1 项目定位明确要求支持两种模型；
- 独立服务器场景在 1.0 验收门槛（计划 §6.2）中是必须项。
