# ADR-004: 严格正确性与世界生成顺序政策

- **状态**：Accepted
- **日期**：2026-07-31
- **决策者**：SteadyChunks 项目

## 上下文

Minecraft 世界生成在原版本身存在执行顺序非确定性（MC-55596 等）。C2ME 等并行化模组通过"保持原版 parity"承诺：相同 seed 下结果与原版一致（但不保证跨运行一致）。

SteadyChunks 引入：

- 任务调度重排（完成优先、优先级评分、背压）
- 软取消（阻止未开始阶段、释放资源）
- 结构选址缓存
- Jigsaw 元数据缓存
- FEATURES 拆分观测

这些都会改变任务执行顺序，可能影响世界生成结果。同时冒险整合包中常见的第三方结构模组可能依赖特定执行顺序或存在隐含线程安全问题。

## 决策

SteadyChunks 采用**严格正确性政策**：

### 4.1 不改变世界生成结果

- **结构位置**：相同 seed 下结构起点、Piece 列表、包围盒、引用结果与原版完全一致；
- **方块状态**：FEATURES 阶段写入的方块状态、方块实体、Loot 与原版一致；
- **光照结果**：光照传播结果与原版一致（或与 Bye-Pregen YALight 一致，若 YALight 启用）；
- **存档格式**：不修改 RegionFile 与序列化格式；
- **种子与随机**：不修改世界种子、结构位置、战利品、方块状态或生成概率（计划 §3 非目标）。

### 4.2 缓存只缓存纯函数与只读元数据

**可缓存**：

- 结构选址中纯函数判断（生物群系允许性、StructureSet placement 候选）
- 区块级高度摘要（已计算的）
- registry / datapack 查找结果
- Jigsaw 模板尺寸、连接点元数据、静态过滤结果
- 旋转/镜像后的坐标变换表
- 不依赖位置与随机数的 Processor 静态结果（`PURE_STATIC`）

**不可缓存**：

- 依赖随机数当前位置的最终 Piece 选择
- 依赖动态 Processor 或 datapack 状态的最终方块结果
- 跨世界共享的可变结构对象
- 经过随机 Processor 后的最终方块列表
- 与世界高度、邻块、群系或位置相关的结果
- Loot、实体或方块实体最终 NBT
- 依赖随机调用次数的结果

### 4.3 数据包重载与维度卸载全量失效

- 数据包重载时清空所有缓存（使用 generation ID 标识）；
- 维度卸载时取消等待任务、释放缓存引用；
- 服务器关闭时拒绝新任务并安全排空。

### 4.4 安全等级分类

按计划 §5.4，所有阶段按线程安全能力分级：

- **A**：已知可并行，且不进行共享可变世界写入
- **B**：在同一 Chunk 或受控邻域内可并行
- **C**：依赖模组实现，需兼容白名单或运行时降级
- **D**：必须串行或在原版指定线程执行

未经证明的模组世界生成代码默认按 C 或 D 处理。

### 4.5 不跨 Tick 保存函数栈

- 不在任务执行中强行中断；
- 不跨 Tick 保存任意函数栈；
- 仅在任务边界（阶段开始前 / 完成后）做取消与状态转换；
- FEATURES 中的结构或特征放置不可中断（ADR-005）。

### 4.6 一致性测试

按计划 §11.1，分两种模式验证：

**严格一致性测试**（可确定路径）：
- 固定世界种子、模组、datapack、线程策略
- 对指定区域计算规范化哈希
- 比较结构起点、Piece、方块、流体、Heightmap、方块实体、结构引用

**语义一致性测试**（原版本身存在非确定性）：
- 结构位置一致、结构完整、无缺块、无引用丢失
- 方块实体与 Loot 合法
- 无越界和非法状态
- 同配置重复运行差异不超过对照组自身差异

## 后果

### 正面

- 用户存档安全，无世界损坏风险；
- 与 FastNoise / Bye-Pregen 的 vanilla parity 承诺对齐；
- 第三方结构模组即使未适配也能安全运行（保守降级）；
- 性能优化不以正确性为代价，符合项目核心约束。

### 负面

- 缓存范围受限，部分高收益缓存（如 Jigsaw 最终 Piece 列表）不可用；
- 必须维护 generation ID 与全量失效逻辑；
- 一致性测试矩阵庞大，CI 成本高；
- 第三方模组线程安全问题无法主动修复，只能报告（计划 §6.5）。

## 备选方案

### A. 允许在严格证明安全后改变世界生成顺序

被否决：Minecraft 世界生成的执行顺序依赖极其复杂（涉及随机数调用次数、邻块状态、模组 hook），"严格证明"在工程上不可行。SteadyChunks 选择保守不改变。

### B. 提供配置项允许用户接受世界生成结果变化以换取性能

被否决：
- 默认行为必须正确，否则用户存档可能损坏；
- 一旦允许变化，无法回滚已生成的区块；
- 项目验收门槛（计划 §6.1）要求无区块损坏、结构错误、光照错误，与允许变化矛盾。

### C. 仅在 FEATURES 阶段允许顺序变化（原版本身非确定）

被否决：FEATURES 阶段的随机数调用顺序仍会影响 Loot、方块实体 NBT 等，玩家可感知。保持原版语义最安全。
